Задача: рекомендовать пользователю товары, которым он поставил бы 4–5 звёзд. Используются оценки, время отзыва и метаданные товара (`title`, `store`, `main_category`). Данные загружаются из [официального репозитория датасета](https://huggingface.co/datasets/McAuley-Lab/Amazon-Reviews-2023/tree/main): `benchmark/5core/rating_only/Software.csv` и `raw/meta_categories/meta_Software.jsonl`. Контрольные суммы SHA-256 и точные адреса файлов указаны в первом кодовом блоке ноутбука. Сами данные в GitHub не включены.

## Как запустить

Из корня проекта:

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m pip install notebook
.venv\Scripts\python -m notebook experiments.ipynb
```

На Linux/macOS команды активации и путь к Python в `.venv` отличаются. Если Jupyter Notebook не установлен, можно открыть `experiments.ipynb` в VS Code или JupyterLab. Первый запуск скачивает примерно 330 МБ файлов в `data/`; нужен интернет. Затем нужно последовательно выполнить все ячейки. Ноутбук в репозитории уже сохранён с результатами выполнения.

## Методика

- Выбор 1500 товаров и 8000 наиболее активных пользователей с не менее чем 8 прежними отзывами делается только по истории **до 01.04.2016**. Полученная выборка содержит 126 617 взаимодействий, 8000 пользователей и 1500 товаров.
- Обучение: до 01.04.2016; валидация: 01.04–31.12.2016; тест: с 01.01.2017. Подбор двух конфигураций каждого метода только по валидации, основная метрика `NDCG@10`.
- В каждой оценке кандидаты — все товары обучающего каталога; просмотренные пользователем товары исключаются. Метрики `NDCG@10` и `Recall@10` считаются на одних и тех же пользователях, у которых есть релевантный отложенный отзыв (`rating >= 4`). Дополнительно измеряется `coverage@10`.
- Пять реализаций в `models/`: `ItemKNN`, `ImplicitALS`, `EASE`, `FactorizationMachine` и `RatingTargetIALS`. У FM, помимо ID, используются слова из названия, магазин и категория. Для обучения FM на каждый положительный отзыв случайно выбирается один неизвестный товар как отрицательный пример; это приближение, так как неизвестный товар не обязательно не нравится пользователю. Никаких готовых библиотечных реализаций рекомендательных алгоритмов нет.
- Пятый метод меняет целевое значение iALS: для известной оценки `p_ui = clip((rating_ui - 3) / 2, 0, 1)`. Таким образом, оценки 1–3 дают 0, оценка 4 даёт 0.5, оценка 5 даёт 1. Коэффициент уверенности остаётся таким же, как в обычном iALS. Это сравнение изолирует влияние целевой функции.

## Результаты на тесте

Одинаковые 1831 пользователя с релевантными отложенными отзывами; все значения при `K=10`:

| Модель | Recall@10 | NDCG@10 |
|---|---:|---:|
| EASE | 0.1083 | 0.0635 |
| ItemKNN | 0.0982 | 0.0578 |
| iALS | 0.0892 | 0.0547 |
| RatingTargetIALS | 0.0818 | 0.0504 |
| FM | 0.0642 | 0.0382 |

EASE оказался лучшим в этом эксперименте. Изменение цели ALS снизило качество относительно iALS. Метаданные слегка улучшили FM на валидации, но FM рекомендует слишком узкий набор товаров; подробные результаты и графики находятся в ноутбуке.
